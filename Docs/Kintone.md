# kintone コネクター

kintone のアプリを、Codeer.LowCode.Blazor のデータソースとして扱うためのライブラリです。
モジュールを kintone のアプリに結び付けると、いつもの一覧・検索・詳細・保存の操作がそのまま kintone のレコードの読み書きになります。
URL・JSON・SQL・kintone のクエリを手で書く必要はありません。

- 一覧・検索・件数・作成・更新・削除: kintone の REST API
- 集計: 条件に合うレコードを kintone から読んで、コネクターが計算
- テーブル (サブテーブル): 親のモジュールの一覧として、親のレコードと一緒に読み書き
- 選択肢の取り込み (デザイナ)・kintone のアカウントでのアプリへのログイン (アカウントの確認)
- 認証: アプリの API トークン、またはパスワード認証 (連携用のアカウント)

> この版は実物の kintone での動作確認がまだ済んでいません (HTTP の偽物と、手元で動くモックを相手にしたテストだけ)。
> 実物で使う前に、検証用の kintone の環境で動作を確かめてください。確かめていない点は下の「実物の kintone で確かめていないこと」にあります。

kintone の環境が無いうちは、手元で動く kintone のモックで、モジュールの作成から一覧・保存までを試せます ([KintoneMock.md](KintoneMock.md))。

## 使い方の流れ

1. kintone 側で API トークンを発行し、アプリ ID を調べる
2. アプリとデザイナに kintone のデータソースを書く
3. アプリとデザイナにコネクターを組み込む
4. デザイナでメタ情報を取り込み、DB のテーブルと同じ手順で kintone のアプリからモジュールを作る

## 1. kintone 側の準備

### API トークン

扱うアプリごとに、アプリの設定の「API トークン」でトークンを発行します。

- **アクセス権**: 画面で使う操作に合わせて付けます。読むだけのアプリは「レコード閲覧」、作成・更新・削除する画面があれば「レコード追加」「レコード編集」「レコード削除」も付けます。
  フォームの設定 (フィールドの定義・選択肢) の読み取りも、このトークンで行います
- **アプリを更新する**: トークンの発行・権限の変更のあとは、アプリの設定で「アプリを更新」を押して反映させます
- **ルックアップがあるとき**: ルックアップの参照元のアプリのトークン (レコード閲覧) も要ります。参照元のアプリもデータソースの `Apps` に書き、そのトークンを `ApiTokens` に並べてください
- コネクターは、データソースに書いたトークンを要求のたびに全部付けて送ります。kintone の制限で、1 回の要求に付けられるトークンは 9 個までです。
  10 個以上のアプリを扱うときは、データソースを分けるか、パスワード認証にします (アプリどうしのリンク・ルックアップは同じデータソースの中でしか結べません)

API トークンで書き込んだレコードの更新者は、kintone では Administrator になります。

### アプリ ID

アプリを開いたときの URL の `/k/` の後ろの数字がアプリ ID です (`https://example.cybozu.com/k/12/` なら 12)。
ゲストスペースのアプリは `https://example.cybozu.com/k/guest/<スペースID>/<アプリID>/` の形で、スペース ID も設定に書きます。

開発用と運用用でアプリ ID が違っても、データソースで付ける表名 (下の `Apps`) を同じにすれば、モジュールのデザインはそのまま使えます。

### パスワード認証にするとき

API トークンの代わりに、連携用の kintone のアカウントのログイン名とパスワードでつなぐこともできます (`User` / `Password`)。

- 読み書きはそのアカウントの kintone の権限で行われます。扱うアプリ・レコード・フィールドを読み書きできる権限を付けてください
- 書き込んだレコードの更新者は、そのアカウントになります
- kintone の仕様で、2 要素認証や SAML 認証だけのアカウントはパスワード認証を使えません
- トークンの数の制限 (9 個) はありません

kintone で実行される主体は、この API トークン (か連携用のアカウント) です。アプリにログインした利用者ごとの権限は、モジュールの権限設定で決めます。

### つながる URL

- `https://` でつながる kintone の URL (`https://example.cybozu.com` のような形) を使います。コネクターは、手元のモック以外への `http://` の接続を受け付けません
- コネクターはリダイレクトに従いません。転送された先の最終の URL を書いてください
- Basic 認証・クライアント証明書を求める環境には、まだ対応していません

## 2. データソース

アプリの `appsettings.json` とデザイナの設定の DataSources に、DB と同じ並びで書きます。`ConnectionString` を `Provider=Kintone;` で始めたものが kintone のデータソースです。

```json
{
  "DataSources": [
    {
      "Name": "Kintone",
      "DataSourceType": "PostgreSQL",
      "ConnectionString": "Provider=Kintone;Host=https://example.cybozu.com;Apps=Customer:12,Order:13;ApiTokens=<APIトークン>,<APIトークン>"
    }
  ]
}
```

`DataSourceType` は `PostgreSQL` にします (kintone 用の値はありません。コネクターが PostgreSQL の書き方で組まれた問い合わせを読み替えます)。

| キー | 必須 | 内容 |
|---|---|---|
| `Provider` | ○ | `Kintone` |
| `Host` | ○ | kintone の URL (`https://` で始める)。`http://` は、このマシン自身 (`localhost`・`127.0.0.1`) で動かすモックのときだけ使えます |
| `Apps` | ○ | `表名:アプリID` をカンマで並べます (例 `Customer:12,Order:13`)。表名はここで付ける名前で、モジュールの DbTable になります。表名に `.` と `"` は使えません。同じ表名・同じアプリ ID を 2 回書けません |
| `ApiTokens` | ※ | API トークンをカンマで並べます (9 個まで) |
| `User` | ※ | パスワード認証のログイン名 (`:` は使えません) |
| `Password` | ※ | パスワード認証のパスワード |
| `GuestSpaceId` | | ゲストスペースのアプリのとき、スペース ID。データソースのアプリは全部そのゲストスペースのものにします |
| `MaxRows` | | 件数を絞らない読み出し・集計で読むレコードの上限。既定 10000。超えると (黙って切り捨てずに) エラーになります |
| `TimeoutSeconds` | | 1 回の要求のタイムアウト (秒)。既定 100 |

※ `ApiTokens` か `User` / `Password` のどちらか一方を書きます (両方は書けません)。

API トークン・パスワードは DB の接続文字列と同じ扱いにしてください (デザインのファイルやリポジトリに入れない。運用環境では環境変数やシークレットストアから渡す)。

## 3. 組み込み

| プロジェクト | パッケージ |
|---|---|
| アプリ (サーバー) | `Codeer.LowCode.Blazor.Connectors.Kintone.Server` |
| デザイナ | `Codeer.LowCode.Blazor.Connectors.Kintone.Designer` |

### アプリ (サーバー)

`ModuleDataIO` に渡す `IDbAccessor` を `KintoneDbAccessor` で包みます。

```csharp
using Codeer.LowCode.Blazor.Connectors.Kintone.Server;

DbAccess = new DbAccessor(SystemConfig.Instance.DataSources);
var kintone = new KintoneDbAccessor(DbAccess, KintoneConnection.FromDataSources(SystemConfig.Instance.DataSources));
ModuleDataIO = new CustomizedModuleDataIO(Design.DesignData, this, kintone, TemporaryFileManager);
```

`KintoneConnection.FromDataSources` は、同じ設定のデータソースには同じ接続を返します (要求のたびに作り直しても、接続とアプリの定義は使い回されます)。

### デザイナ

`IDbAccessorFactory` の実装で `IDbAccessor` を包みます。

```csharp
using Codeer.LowCode.Blazor.Connectors.Kintone.Designer;

public class DbAccessorFactory : IDbAccessorFactory
{
    public IDbAccessor Create(DataSource[] dataSources)
        => KintoneDesignerInitializer.CreateDbAccessor(new DbAccessor(dataSources), dataSources);
}
```

デザイナのアプリの `OnStartup` に 2 行足します。

```csharp
protected override void OnStartup(StartupEventArgs e)
{
    KintoneDesignerInitializer.Initialize(DesignerEnvironment);   //base.OnStartup より前
    base.OnStartup(e);
    KintoneDesignerInitializer.Setup(DesignerEnvironment);        //base.OnStartup の後
}
```

- `Initialize`: AI (Claude Code など) が kintone のモジュールを設計するための仕様の文書を登録します。デザイナがアプリの定義を、下のメタ情報のファイルから読むようになります
- `Setup`: メニュー **Tools > kintone のメタ情報を更新** を足します

kintone 以外のデータソースは、包んだ `DbAccessor` がこれまでどおり処理します。

組み込んだデザイナの見本は [Source/Example/LowCodeApp.Designer](../Source/Example/LowCodeApp.Designer) にあります (`App.xaml.cs` と `DbAccessorFactory.cs`)。

### デザイナはメタ情報をファイルから読む

デザイナは、kintone のアプリの定義 (メタ情報) をプロジェクトのフォルダのファイル `kintone.<データソース名>.metadata.json` から読みます。
プロジェクトを開くたびに kintone へ取りに行くことはありません。

- **取り込み・更新**: メニュー **Tools > kintone のメタ情報を更新**。`Apps` に書いたアプリのフォームの設定を kintone から取り直してファイルに保存します。
  最初の 1 回と、kintone でフィールド・選択肢を変えたとき・`Apps` にアプリを足したときに実行してください。ファイルが無いうちは、kintone のアプリはデザイナに出ません
- **中身**: 表名と、フィールドごとのフィールドコード・フィールドの種類・画面の項目名・読み取り専用・必須・重複禁止・ルックアップかどうか・選択肢・テーブルの中のフィールドだけです。
  接続の情報 (URL・アプリ ID・トークン・パスワード) とレコードは入りません。デザインのファイルと一緒にリポジトリへ入れておけば、kintone に接続できない環境でもデザインできます
- 更新に失敗したときは、前のファイルがそのまま残ります
- アプリ (サーバー) はこのファイルを使いません。実行時はアプリごとに kintone からフォームの設定を読み、アプリが動いている間は持ち続けます。kintone でフィールドを変えたらアプリを再起動してください

## 4. モジュールを作る

デザイナのデータソースに、`Apps` に書いた kintone のアプリが DB のテーブルと同じように並びます。テーブルからモジュールを作るのと同じ手順で作れます。

| モジュールの設定 | kintone では |
|---|---|
| DataSourceName | kintone のデータソース名 |
| DbTable | `Apps` で付けた表名 (アプリの名前・アプリ ID ではありません) |
| フィールドの DbColumn | フィールドコードそのまま (日本語のコードもそのまま) |
| Id フィールド | DbColumn は `$id` (kintone のレコード ID) |

`$id` (レコード ID) と `$revision` (レコードのリビジョン) は、どのアプリにも列として出てきます。
関連レコード一覧・ラベル・罫線・スペース・グループは列として出てきません。名前に `"` を含むフィールドコードは扱えません。

使うフィールドだけをフィールドにしてください。フィールドにしていないフィールドは読みも書きもしません。

### Id

モジュールの Id は、ふつうは kintone のレコード ID (`$id`) です。kintone が採番するので、Id は手入力にしません。新規の保存のあと、kintone が付けたレコード ID が入ります。

重複禁止にした文字列 (1 行)・数値のフィールド (顧客コードなど) を Id にすることもできます。
ほかのアプリがそのコードで指しているとき (ルックアップのキーなど) に使います。Id フィールドを手入力 (`IsManualInput`) にして、詳細の画面で入力させます。
それ以外のフィールドを Id にすると、更新・削除がエラーになります。

### フィールドの型

| kintone のフィールド | 列の型 | フィールド |
|---|---|---|
| 文字列 (1 行)・リンク | 文字列 | TextField |
| 文字列 (複数行) | 文字列 | TextField (複数行) |
| リッチエディター | 文字列 (HTML) | TextField (複数行)。値は HTML のまま読み書きされる |
| 数値 | 数値 | NumberField |
| 計算 | 数値。表示形式が日時・日付・時刻ならその型、時間・日数と時間なら文字列 | 型に合うフィールド (読み取り専用) |
| 日付 | 日付 | DateField |
| 時刻 | 時刻 | TimeField |
| 日時・作成日時・更新日時 | 日時 (UTC) | DateTimeField (SaveAsUtc をオン) |
| ラジオボタン・ドロップダウン | 文字列 (選択肢の文字) | SelectField (下の「選択肢」) |
| レコード番号・ステータス | 文字列 | TextField (読み取り専用) |
| 作成者・更新者 | 文字列 (ログイン名) | TextField (読み取り専用) |
| チェックボックス・複数選択 | 文字列 (JSON の配列 `["A","B"]`) | 下の「値が複数のフィールド」 |
| ユーザー選択・組織選択・グループ選択 | 文字列 (JSON の配列 `[{"code":"...","name":"..."}]`) | 下の「値が複数のフィールド」 |
| 作業者・カテゴリー・添付ファイル | 文字列 (JSON の配列) | 表示だけ (読み取り専用) |
| テーブル | 文字列 (行の JSON の配列) | 親のモジュールの一覧 (下の「テーブル」) |

- **kintone の日時は UTC です。** 日時の列は UTC の日時として読み書きします。デザイナはこの列の DateTimeField の SaveAsUtc を既定でオンにします。オフにしないでください (時差の分ずれます)
- 時刻・日時は kintone が分までしか持ちません (秒は保存されません)
- kintone に真偽の型はありません。はい / いいえは、ラジオボタン・ドロップダウンを SelectField にします
- 計算フィールドの値が読めない形のときは空として読みます
- kintone で必須のフィールドも、列としては空を許す形で見えます。必須かどうかは保存のときに kintone が確かめ、足りなければ保存がエラーになります (どの項目かがメッセージに出ます)。
  画面で先に止めたいときは、フィールドを必須にしてください (メタ情報のファイルの列が `"Required": true`)

### 選択肢

ラジオボタン・ドロップダウン・チェックボックス・複数選択の選択肢は、メタ情報の更新のときに取り込みます (メタ情報のファイルの列の `Options`。kintone の画面の順)。

- 画面では、選択肢を CLB の Enum の定義に写し、フィールドを Enum の選択 (SelectField) にします。保存されるのは選択肢の文字です
- 選択肢を画面のたびに kintone から読むことはしません。kintone で選択肢を変えたら、メタ情報を更新して Enum の定義を直してください

### 値が複数のフィールド

チェックボックス・複数選択・ユーザー選択・組織選択・グループ選択は、値が JSON の配列の文字列の列になります。

- 読む値: チェックボックス・複数選択は `["A","B"]`、ユーザー選択などは `[{"code":"taro","name":"山田 太郎"}]`。1 つも選ばれていなければ空
- 書く値: 同じ形の JSON の配列。ユーザー選択などは `["taro"]` (コードの文字だけ) でもかまいません。空 (空欄・`[]`) にすると全部外れます
- 検索: 「等しい」「候補のどれか (In)」は「その値を含む」の意味になります (ユーザー選択などはコード = ログイン名で探します)。「空欄」も使えます

### 読み取り専用のフィールド

次のフィールドは、読み取り専用の列として見えます (メタ情報のファイルの `"ReadOnly": true`)。

- `$id`・`$revision`
- 計算・レコード番号・作成者・更新者・作成日時・更新日時・ステータス・作業者・カテゴリー・添付ファイル
- 自動計算する文字列 (1 行)
- ルックアップでコピーされるフィールド (コピー先)

レイアウトで表示専用 (IsViewOnly) にして置きます。新規で空のときは送りません。値を入れて保存するとエラーになります。
計算・ルックアップでコピーされる値は、保存のあとで読み直すと出ます。

### ほかのアプリとの関係

- ほかのアプリを指すフィールドは、相手のアプリのモジュールを作って LinkField で結びます。一覧・詳細で相手の項目 (会社名など) を表示できます。
  相手をレコード ID で指しているなら相手の Id、顧客コードのようなフィールドで指しているならそのフィールドの値に結びます
- **ルックアップ**: キーのフィールドに値を保存すると、kintone が参照元のアプリからコピー先のフィールドへ値を写します。
  キーのフィールドを LinkField (か TextField) にし、コピー先のフィールドは読み取り専用にします。参照元に無い値を保存すると、kintone がエラーにします。
  参照元のアプリのトークンも要ります (上の「API トークン」)
- **関連レコード一覧**に当たる画面は、相手のアプリのモジュールの一覧 (ListField) を置き、相手の側のフィールドとこちらのフィールドの値が等しい条件で絞って作ります
- 結べるのは同じ kintone のデータソースのアプリ同士です。kintone のアプリと DB のテーブルは結合できません

### テーブル

kintone のテーブルは、親のアプリの列 (テーブルのフィールドコード) として見え、値は行の JSON の配列です。
画面では、親のモジュールに一覧 (ListField) を置いて行を表示・編集します。作りは「行データを親の列に JSON 配列で保存する一覧」(ListField の DbColumn と、行のモジュールの JsonField) と同じです。

| 設定 | 書く値 |
|---|---|
| 親の ListField の DbColumn | テーブルのフィールドコード |
| 行のモジュール | Id フィールドなし。JsonField 1 つに、行の項目をノードとして並べる |
| ノードのキー・行のフィールドの DbColumn | テーブルの中のフィールドコードそのまま (メタ情報のファイルの、テーブルの列の `Fields`) |

- 読む値: 行ごとに `{"$id": "行ID", "フィールドコード": 値, ...}`。数値は JSON の数値、日付・時刻・日時は kintone の文字のまま (日時は UTC)、値が複数のフィールドは配列のまま、未入力は null。行が無ければ列は空
- 行の ID (`$id`) はノードにしなくてかまいません。読んだ行に残り、保存のときに使われます
- 保存: 行の ID がある行はその行 (送った項目だけ変わる)、無い行は新しい行になります。**画面で消した行 (送った配列に無い行) は kintone が削除します** (kintone のテーブルの更新の仕様です)
- 行の中の読み取り専用のフィールド (計算・ルックアップのコピー先) と、定義に無い項目は送りません。ノードにしていない項目は、今ある行では変わらず、新しい行では空 (kintone の初期値) になります
- テーブルは親のレコードと一緒に 1 回で保存されます (行ごとに分かれません)
- 親のテーブルの列を検索条件・並び・集計に使うとエラーになります。テーブルの行を親をまたいで一覧・検索・集計することはできません

### 論理削除・楽観ロック

- **楽観ロック**: `OptimisticLocking` のフィールド (版を上げる設定) を `$revision` に結びます。
  更新・削除の要求に読んだときのリビジョンを付けて送り、ほかの人が先に (kintone の画面や別の画面から) 更新していれば、kintone が弾いて保存がエラーになります。
  確かめてから書くまでが kintone の中で一度に行われるので、その間に入る更新も防げます。リビジョンは kintone が進めます
- **論理削除**: 削除済みを 1 で持つ数値のフィールドを kintone のアプリに作り、`LogicalDelete` の BooleanField を結びます (kintone の画面には削除済みのレコードも出ます)。
  論理削除の条件が付いた更新・削除は、条件に合うレコードがあるかを先に確かめてから書きます (確かめてから書くまでの間に入った変更は、楽観ロックがあれば kintone が弾きます)

## 動き

### 一覧・検索

モジュールの検索条件・並び・ページング・件数は、kintone のクエリになって kintone で実行されます。

使える検索条件:

- 比較 (等しい・等しくない・大小・範囲)・部分一致・空欄かどうか・候補のどれか (In)
- 条件の組み合わせ (かつ・または・否定)
- LinkField の値での検索 (例: 受注を顧客で絞る)
- LinkField 越しの項目での検索 (例: 受注を顧客の会社名で絞る。リンク先のリンクの項目も)
- 子の一覧の項目での検索 (例: ある商品の明細を持つ受注。すべて含む・存在する/しない・否定も)
- LinkField 越しの項目での並べ替え

kintone のフィールドの種類ごとに、使える条件が決まっています。使えない組み合わせはエラーになります (条件を落として読むことはしません)。

| フィールド | 使える条件 |
|---|---|
| 文字列 (1 行)・リンク | 等しい・等しくない・部分一致・In・空欄 |
| 数値・計算・レコード ID (`$id`) | 等しい・等しくない・大小・In・空欄 |
| 日付・時刻・日時・作成日時・更新日時 | 等しい・等しくない・大小・空欄 |
| 文字列 (複数行) | 部分一致・空欄 (等しい・In は使えない) |
| リッチエディター | 部分一致 (「含まない」・空欄は使えない) |
| ラジオボタン・ドロップダウン・ステータス・作成者・更新者 | 等しい・等しくない・In・空欄 (部分一致・大小は使えない) |
| チェックボックス・複数選択・ユーザー選択など | 等しい (= 含む)・In・空欄 |
| レコード番号 | 等しい・等しくない・大小・In (値は番号の数字) |
| テーブル・添付ファイル・`$revision` | 使えない |

- 空欄の扱いは DB と同じ意味になるように書きます。「等しくない」「含まない」「In でない」は、空欄の行には当たりません
- **部分一致は kintone の検索の動きに従います。** kintone の部分一致は語の単位の検索なので、文字の途中からの一致が見つからないことがあり、DB の部分一致と同じ結果になるとは限りません
- 並べられるのは、文字列 (1 行)・数値・計算・日付・時刻・日時・ラジオボタン・ドロップダウン・レコード番号・レコード ID など、kintone が並べられるフィールドです。複数行の文字列・値が複数のフィールド・テーブルでは並べられません
- 文字の比較と並びは kintone に従います。DB と同じ結果になるとは限りません

ページング:

- kintone から 1 回に読むのは 500 件までで、続きは繰り返し読みます
- **ページングで読めるのは、条件に合うレコードの先頭から 10000 件までです** (kintone の制限)。それより後ろのページはエラーになります。件数の多いアプリの一覧は、検索条件で絞れるようにしてください
- 件数を絞らない読み出しは、`MaxRows` を超えたらエラーにします (黙って切り捨てません)。一覧には表示件数を設定してください。並びの無い読み出しはレコード ID の順に読み進めるので、10000 件の制限には当たりません

LinkField 越しの項目 (顧客の会社名など) の表示は、主のアプリを読んだあと相手のアプリをまとめて読み、コネクターが突き合わせます。

LinkField 越しの項目・子の一覧の項目での検索は、コネクターが先に相手のアプリを条件で読んで値を集め、主のアプリを「集めた値のどれかに一致」で読みます。条件の「かつ・または・否定」の意味は DB と同じです。

- 集めた値は、1 回の問い合わせに 100 個まで入れます。収まらないときは、問い合わせを分けて読み、コネクターが重なりを除いて並べ、ページを切ります
- 相手のアプリで当たったレコード・コネクターが読んだレコードが `MaxRows` を超えたときは、黙って切らずにエラーにします。相手のアプリで当たる件数が多い条件は、ほかの条件と組み合わせて絞ってください
- LinkField 越しの項目での並べ替えは、条件に合うレコードを全部読み (`MaxRows` まで)、コネクターが並べてページを切ります。件数の多い一覧で使うときは、ほかの条件で絞ってください
- コネクターが並べるときは、空欄は昇順で先、文字は文字コードの順です。kintone が並べる順とは違うことがあります

### 集計

集計 (件数・重複なしの件数・合計・平均・最小・最大を項目ごとにまとめる機能) が使えます。軸・条件・集計後の絞り込み・並び・上位の件数・クロス集計も使えます。

- **kintone に集計の機能は無いので、条件に合うレコードを全部読んでコネクターが集計します** (`MaxRows` まで。超えたらエラー)。件数の多いアプリの集計には、期間などの条件を必ず付けてください
- 日付の項目を期間 (年・四半期・月・週・日・時) でまとめる軸は使えません。kintone のアプリに期間の計算フィールド (例: `DATE_FORMAT(受注日, "YYYY-MM", "Asia/Tokyo")`) を作り、その項目を軸にしてください
- 集計の結果をコネクターが並べるときの空欄・文字の扱いは、上の「一覧・検索」と同じです

### 保存

| 操作 | kintone への要求 |
|---|---|
| 新規 | レコードの作成。kintone が返したレコード ID が Id になる (Id が重複禁止のフィールドなら、入力した値) |
| 更新 | レコード ID (または Id にした重複禁止のフィールドの値) を指定して、変更したフィールドだけを更新する。楽観ロックがあればリビジョンも付ける |
| 削除 | レコードの削除 (論理削除のモジュールでは、論理削除のフィールドの更新)。楽観ロックがあればリビジョンも付ける |

- 新規では、空のフィールドを送りません (kintone のフォームの初期値が入ります)
- 更新・削除しようとしたレコードが無いとき・リビジョンが違うときは、更新・削除されません (楽観ロックのモジュールでは、ほかの人が先に更新したときと同じエラーになります)
- kintone の必須・重複禁止・値の範囲・選択肢に無い値は kintone 側で確かめられます。保存が止められたときは、kintone のメッセージ (項目ごとのメッセージを含む) のエラーになります
- **kintone への保存はレコード 1 件ごとに確定します。ロールバックはしません。** 同じ保存の中のほかの処理が失敗しても戻りません。
  1 回の保存で kintone のレコードを複数書く画面 (親と、別のアプリの子の一覧) や、kintone と DB を一緒に書く画面は、途中まで保存された状態が起こりえます。
  そろっていないと困る組み合わせは、kintone のテーブルにする (親と一緒に 1 回で保存されます) か、画面を分けてください
- 一括の追加は 1 件ずつ作ります。途中で失敗したときは、エラーのメッセージに作成済みの件数とキーが入ります (作成済みのレコードは残ります)。照合してから続きを保存してください
- 書き込みを送ったあと応答を受け取れなかった場合 (通信の失敗・タイムアウト・エラーコードの無いサーバー側の失敗) は、実行されたかどうかが分かりません。
  コネクターはやり直さず (二重に作らないため)、`WriteResultUnknown` のエラーにします。kintone 側で結果を確かめてください
- 保存は接続の API トークン (か連携用のアカウント) の権限で行われます。画面のユーザーごとの kintone の権限にはなりません

## kintone のアカウントでのログイン

アプリの利用者が、kintone のログイン名とパスワードでアプリにログインできるようにする部品です。コネクターはアカウントを確かめるだけで、ログインの画面・Cookie の発行・利用者の表との突き合わせはアプリ (ホスト) が行います。

```csharp
var connection = KintoneConnection.FromDataSources(SystemConfig.Instance.DataSources).First(e => e.Settings.Name == "Kintone");
var result = await connection.VerifyAccountAsync(loginName, password);
switch (result.Status)
{
    case KintoneAccountStatus.Succeeded:          //result.LoginName で利用者の行を引いてログインさせる
    case KintoneAccountStatus.InvalidCredentials: //ログイン名かパスワードが違う
    case KintoneAccountStatus.Failed:             //確かめられなかった (kintone に届かないなど)。result.Message はログ用
}
```

- 利用者のログイン名とパスワード (パスワード認証) で、kintone に要求を 1 回送ります (やり直しません)。kintone が認証を拒んだら、ログイン名かパスワードが違うとします
- ログイン名・パスワードが空のとき、ログイン名に `:` を含むときは、送らずに「違う」とします
- 成功したときの `LoginName` は、入力されたログイン名のままです
- kintone の仕様で、2 要素認証や SAML 認証だけの利用者はパスワード認証を使えないため、この確認は通りません
- パスワードはどこにも保存しません (結果・メッセージ・例外に入りません)。連携用の接続には触りません
- 失敗しても例外を投げずに結果で返します
- **ログインのあとのデータの読み書きは、連携用の API トークン (か連携用のアカウント) のままです。** 利用者本人の kintone の権限では読み書きしません。利用者ごとの権限は、モジュールの権限設定で決めます
- ログイン名・パスワードの総当たりへの対策 (失敗が続いたらロックする) はアプリが行います

組み込みの見本は Example の `AccountController.LoginKintone` (`/api/account/login_kintone`) と `login.html` です ([Example.md](Example.md))。

## エラー

コネクターの失敗は `KintoneException` で、`Kind` で種類が分かります。`ErrorCode` に kintone のエラーコード (`GAIA_RE01` のような文字)、`StatusCode` に HTTP のステータスが入ります。
メッセージには kintone のメッセージと、項目ごとのメッセージ (先頭の数件) が入ります。API トークン・パスワード・接続文字列はメッセージに入りません。

| Kind | 内容 |
|---|---|
| `NotSupported` | 設定の誤り・コネクターが扱えない操作 (使えない検索条件・SQL の実行など) |
| `Authentication` | 認証の失敗・アクセス権が無い (API トークン・トークンの権限・パスワード) |
| `NotFound` | アプリ・レコードが無い |
| `InvalidRequest` | 入力・kintone の検証のエラー (必須・重複禁止・選択肢・読み取り専用のフィールドへの書き込みなど)、`MaxRows` の超過・ページングの 10000 件の超過、リダイレクトが返った (`Host` の設定を確かめる。要求は処理されていない) |
| `ServiceUnavailable` | kintone 側・通信の障害 (混雑による制限を含む) |
| `WriteResultUnknown` | 書き込みを送ったが、実行されたかどうかが分からない |
| `Unknown` | 上のどれにも当たらない応答 (JSON でない応答・決まった書式で読めない値など) |

読み出しは一時的な失敗 (混雑・障害・通信の失敗) を時間を置いて 3 回までやり直します。書き込みはやり直しません。

## 制限

### kintone の仕様によるもの

- 1 回の要求に付けられる API トークンは 9 個までです (それより多いアプリは、データソースを分けるかパスワード認証にします)
- ページングで読めるのは、条件に合うレコードの先頭から 10000 件までです
- 集計の機能が無いため、集計はレコードを読んでコネクターが計算します (`MaxRows` まで)
- フィールドの種類ごとに使える検索条件・並べられるフィールドが決まっています (上の「一覧・検索」)。部分一致は語の単位の検索です
- 時刻・日時は分までです
- 2 要素認証・SAML 認証だけのアカウントは、パスワード認証 (連携用のアカウント・ログインの確認) に使えません

### コネクターがまだ対応していないもの

今後の版で対応を検討しているものです。

- 添付ファイルのアップロード・ダウンロード (ファイル名などの情報を読むだけです。FileField は結べません)
- プロセス管理の操作 (ステータスを進める・作業者を変える)。ステータスと作業者は読むだけです
- レコードのコメント
- テーブルの行を、親をまたいで一覧・検索・集計すること
- 作成者・更新者・ユーザー選択などの表示名の列 (ログイン名・コードで扱います)
- 日付を期間でまとめる集計の軸
- 利用者本人の kintone の権限での読み書き (OAuth など)
- Basic 認証・クライアント証明書を求める環境

### いまの作りによるもの

- 保存はレコード 1 件ごとに確定し、ロールバックしません (上の「保存」)
- SQL・ストアドプロシージャ (ExecuteSqlField・QueryField などの SQL を直接書く機能) は使えません
- 選択肢はメタ情報の更新のときに取り込むだけです。画面の候補は Enum の定義から出します
- アプリはフォームの設定を起動中ずっと持ちます。kintone でフィールドを変えたらアプリを再起動してください
- kintone のアプリと DB のテーブルは結合できません。結べるのは同じデータソースのアプリ同士です
- 列どうしの比較・JSON の列のノードでの検索・意味検索のようなフィールド独自の検索条件は使えません
- LinkField 越しの項目・子の一覧の項目での検索で相手のアプリに当たる件数、LinkField 越しの項目での並べ替えで読むレコードの件数、LinkField の表示で相手のアプリから読むレコードの件数、集計で読むレコードの件数は `MaxRows` までです
- 一括の追加は 1 件ずつ作ります (kintone のまとめて書く API は使っていません)
- 件数を絞らない読み出しは、kintone のカーソルの機能を使わずに読み進めます

## 実物の kintone で確かめていないこと

この版は、実物の kintone にまだつないでいません。テストの相手は、HTTP の偽物と、公開されている API の説明から作ったモックです。次の点は実物で確かめる必要があります。

- 数値・日付のフィールドの「空欄」「空欄でない」の検索
- 「等しくない」「含まない」「In でない」・大小の比較で、空欄の行が DB と同じ扱いになること
- 「候補のどれか (In)」に入れられる値の数・問い合わせの長さの上限 (いまは 1 回に 100 個まで)
- 数値・レコード ID の条件の書き方
- 件数の数え方と、ページングの 10000 件の境界
- 並べたときの空欄の位置と、並べられないフィールドの種類
- 部分一致の一致のしかた (語の区切り)
- 保存のエラー (無いレコード・リビジョンの違い) の返り方
- 重複禁止のフィールドを Id にしたときの更新
- 何も変えずに保存したときに、リビジョンが進むかどうか
- テーブルの保存 (行の ID がある行は送った項目だけ変わる・送らなかった行は消える)
- kintone のアカウントでのログインの確認 (とくに 2 要素認証・SAML の利用者)
- ゲストスペースのアプリ
