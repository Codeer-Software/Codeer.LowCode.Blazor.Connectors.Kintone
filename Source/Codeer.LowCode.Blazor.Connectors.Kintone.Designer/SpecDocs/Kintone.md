# Kintone (kintone のアプリをモジュールにする)

「kintone の顧客アプリを一覧したい」「kintone のレコードを画面から直したい」と言われたらこれ。
データソースが kintone のモジュールは、**DB のテーブルに結び付けたモジュールと同じ作り**で、読み書きの先が kintone のアプリのレコードになる。
フィールドもスクリプトも専用のものは無い。URL・JSON・SQL・kintone のクエリを書くことも無い。

kintone のデータソースかどうかは、データソースの `ConnectionString` が `Provider=Kintone;` で始まることで分かる (`DataSourceType` は `PostgreSQL` と書かれている)。
扱えるアプリは、データソースの `Apps` (`表名:アプリID` の並び) に書かれたものだけ。要るアプリが無ければ、ユーザーにデータソースの設定へ足してもらう (接続の設定は自分で書き換えない)。

テーブルの定義は、プロジェクトのサーバー専用ファイル (`ServerFiles/kintone.<データソース名>.metadata.json`) から読まれる (kintone には取りに行かない)。
このファイルはデザインと一緒に配られ、Web アプリもここから読む (Web アプリも kintone に定義を取りに行かない)。
kintone のテーブルが 1 つも出てこない・要るアプリやフィールドが無いときは、このファイルが無いか古い。
ユーザーにデザイナのメニュー **Tools > kintone のメタ情報を更新** を実行してもらう (このファイルを手で書き換えない)。更新したら、デザインを配り直すまで Web アプリは前の定義のまま。

## モジュールの作り方

DB のテーブルからモジュールを作るのと同じ手順 (テーブルの定義を読んで、列からフィールドを作る)。kintone のアプリがテーブル、フィールドが列として見える。

| モジュールの設定 | 書く値 |
|---|---|
| `DataSourceName` | kintone のデータソース名 |
| `DbTable` | テーブルの定義の表名そのまま (データソースの `Apps` で付けた名前。アプリの名前・アプリ ID ではない) |
| フィールドの `DbColumn` | テーブルの定義に出てくる列名そのまま (kintone のフィールドコード。日本語のコードもそのまま。`会社名`・`受注日`) |
| Id フィールド | `DbColumn: "$id"` (kintone のレコード ID。kintone が採番する) |

- Id フィールドは既定のまま (手入力にしない)。新規の保存のあと、kintone が付けたレコード ID が入る
- 顧客コードのような「重複を禁止した文字列 (1 行)・数値のフィールド」(メタ情報のファイルの列が `"Unique": true`) を Id にしてもよい。
  その場合は Id フィールドを `IsManualInput: true` にして詳細のレイアウトに置く。ほかのアプリがそのコードで指しているとき (ルックアップのキーなど) に使う
- `$revision` は版 (kintone のリビジョン)。楽観ロックに使う (下の「楽観ロック」)。ほかの用途のフィールドにしない
- 使う列だけをフィールドにする。フィールドにしていない列は読みも書きもしない
- 一覧には表示件数 (ページング) を付ける。件数を絞らない読み出しは上限 (データソースの `MaxRows`、既定 10000 行) を超えるとエラーになる

メタ情報のファイルの列には、kintone のフィールドの種類 (`FieldType`)・画面の項目名 (`Label`)・読み取り専用 (`ReadOnly`)・必須 (`Required`)・重複禁止 (`Unique`)・
ルックアップ (`Lookup`)・選択肢 (`Options`)・テーブルの中のフィールド (`Fields`) が入っている。フィールドの表示名は `Label` から付ける。

### フィールドの種類とフィールド

| kintone のフィールド (`FieldType`) | 列の型 | フィールド |
|---|---|---|
| 文字列 (1 行) `SINGLE_LINE_TEXT`・リンク `LINK` | 文字列 | TextField |
| 文字列 (複数行) `MULTI_LINE_TEXT` | 文字列 | TextField (`IsMultiline: true`) |
| リッチエディター `RICH_TEXT` | 文字列 (HTML) | TextField (`IsMultiline: true`)。値は HTML のまま読み書きされる |
| 数値 `NUMBER` | 数値 | NumberField |
| 計算 `CALC` | 数値 (表示形式が日時・日付・時刻ならその型、時間・日数なら文字列) | 型に合うフィールド。読み取り専用 |
| 日付 `DATE` | 日付 | DateField |
| 時刻 `TIME` | 時刻 | TimeField (分まで。秒は保存されない) |
| 日時 `DATETIME`・作成日時 `CREATED_TIME`・更新日時 `UPDATED_TIME` | 日時 | DateTimeField。**`SaveAsUtc: true`** (kintone の日時は UTC。分まで。秒は保存されない) |
| ラジオボタン `RADIO_BUTTON`・ドロップダウン `DROP_DOWN` | 文字列 (選択肢の文字) | SelectField (下の「選択肢」) |
| レコード番号 `RECORD_NUMBER` | 文字列 | TextField。読み取り専用 |
| 作成者 `CREATOR`・更新者 `MODIFIER` | 文字列 (ログイン名) | TextField。読み取り専用 |
| ステータス `STATUS` (プロセス管理) | 文字列 | TextField。読み取り専用 |
| チェックボックス `CHECK_BOX`・複数選択 `MULTI_SELECT` | 文字列 (JSON の配列 `["A","B"]`) | 下の「値が複数のフィールド」 |
| ユーザー選択 `USER_SELECT`・組織選択 `ORGANIZATION_SELECT`・グループ選択 `GROUP_SELECT` | 文字列 (JSON の配列 `[{"code":"...","name":"..."}]`) | 下の「値が複数のフィールド」 |
| 作業者 `STATUS_ASSIGNEE`・カテゴリー `CATEGORY` | 文字列 (JSON の配列) | 読み取り専用。表示だけ |
| 添付ファイル `FILE` | 文字列 (ファイルの一覧の JSON) | `KintoneAttachmentsFieldDesign` (下の「添付ファイル」)。TextField・FileField は結ばない |
| テーブル `SUBTABLE` | 文字列 (行の JSON の配列) | 親のモジュールの一覧 (下の「テーブル」) |

- kintone に真偽の型は無い。はい / いいえは、ラジオボタン・ドロップダウンの SelectField にする
- 関連レコード一覧・ラベル・罫線・スペース・グループは列として出てこない。関連レコード一覧に当たる画面は、相手のアプリのモジュールの一覧 (ListField) で作る (下の「ほかのアプリを指すフィールド」)

### 選択肢

ラジオボタン・ドロップダウン・チェックボックス・複数選択の選択肢は、メタ情報のファイルの列の `Options` (kintone の画面の順) に入っている。

- 列 1 つにつき、Enum の定義 `Enums/<名前>.enum.json` を作る。`Members` は `Options` の順に、`Value` = 選択肢の文字そのまま。
  選択肢の文字が識別子として使えるなら `Name` も同じ、使えない文字 (空白・記号・数字で始まる) を含むなら `Name` を別の識別子にする
- ラジオボタン・ドロップダウンの列のフィールドを SelectField にして、`EnumName` に Enum の名前を書く。保存されるのは選択肢の文字
- 選択肢は kintone から画面のたびに読み直さない (Enum の定義が正)。kintone で選択肢を変えたら、メタ情報を更新して Enum の定義を直す

### 値が複数のフィールド

チェックボックス・複数選択・ユーザー選択・組織選択・グループ選択は、値が JSON の配列の文字列の列になる。

- 読む値: チェックボックス・複数選択は `["A","B"]`、ユーザー選択などは `[{"code":"taro","name":"山田 太郎"}]`。1 つも選ばれていなければ空 (null)
- 書く値: 同じ形の JSON の配列。ユーザー選択などは `["taro"]` (コードの文字だけ) でもよい。空 (null・空文字・`[]`) にすると全部外れる
- 結ぶフィールドは TextField (JSON の文字のまま出入りする)。画面で直させないなら、レイアウトで `IsViewOnly: true` にする
- 検索: 「等しい」「候補のどれか (In)」は「その値を含む」の意味になる (ユーザー選択などはコード = ログイン名で探す)。「空欄」も使える。部分一致・大小・並びは使えない

### 添付ファイル

添付ファイル (`FILE`) の列は、kintone の添付ファイルのフィールドに結ぶ。1 つのフィールドでその列のファイルの一覧・ダウンロード・追加 (複数)・削除を扱う。

```json
{
  "DbColumn": "Attachments",
  "MaxFileSizeMB": 10,
  "DisplayName": "添付ファイル",
  "Name": "Attachments",
  "TypeFullName": "Codeer.LowCode.Blazor.Connectors.Kintone.KintoneAttachmentsFieldDesign"
}
```

- `MaxFileSizeMB`: 1 ファイルの上限 (MB・既定 10・1 以上)。画面で足すときの確かめで、超えるファイルは画面で足せない (入力エラー)。サーバーでは確かめない (サーバー側の上限は kintone の上限とアプリの要求の大きさの上限)
- 値は kintone の添付ファイルの値の JSON の文字 (`[{"contentType","fileKey","name","size"}...]`)。保存で送られるのは足すファイル (`{"name","contentType","base64"}`) と消すファイル (`{"fileKey","deleted":true}`) だけで、消せるのはそのレコードのその列のファイルだけ
- 足す・消すは保存したときに送られる。新しいレコードでも足せる。ダウンロードのリンクは保存済みのファイルだけ (ダウンロードの口はアプリのホストが置く)
- 一覧のレイアウトの列に置くとファイル名だけが並ぶ。その列は `CanUserSort: false` にする (並べ替えに使えない)
- 検索の条件・並び・集計に使わない (エラーになる)。検索のレイアウトに置かない
- `IsViewOnly`・`IsEnabled`・権限はほかのフィールドと同じ。`IsRequired` は「ファイルが 1 つ以上」
- レコードのコピーでは写らない (コピーしたレコードは添付なしで始まる)
- 値とファイルの操作はスクリプトに出ていない (足す・消すは画面の操作だけ)
- テーブルの中の添付ファイルは読み取り専用 (行の JSON の中の値として読むだけ)

### 読み取り専用の列

計算・レコード番号・作成者・更新者・作成日時・更新日時・ステータス・作業者・カテゴリー、文字列 (1 行) の自動計算、ルックアップでコピーされるフィールド、`$id`・`$revision` は、
メタ情報のファイルで `"ReadOnly": true` になっている。

- 型に合うフィールドを結び、**詳細・一覧のレイアウトで `IsViewOnly: true`** にする (表示だけ)
- `IsRequired` にしない。新規では空のまま送られない。値を入れて保存するとエラーになる
- 計算・ルックアップでコピーされる値は、保存のあとで読み直すと出る (保存の前の画面では空・前の値のまま)

### 必須・重複禁止・初期値

kintone で必須・重複禁止のフィールドも、列としては空を許す形で見える。保存のときに kintone が確かめ、足りない・重なっていれば保存がエラーになる (どの項目かがメッセージに出る)。
画面で先に止めたいときは、フィールドを `IsRequired: true` にする (メタ情報のファイルの列が `"Required": true`)。
新規で空のフィールドは送られないので、kintone のフォームの初期値が入る。

### ほかのアプリを指すフィールド (ルックアップ・外部キー)

- 相手のアプリのモジュールを作り、LinkField で結ぶ (`SearchCondition.ModuleName` = 相手のモジュール、`ValueVariable` = 相手の側で指されているフィールドの値、`DisplayTextVariable` = 見せる項目)。
  相手をレコード ID で指しているなら `ValueVariable: "Id.Value"`、顧客コードのようなフィールドで指しているならそのフィールドの `Value`
- kintone のルックアップ (メタ情報のファイルの列が `"Lookup": true`) は、キーのフィールドに値を保存すると、kintone が相手のアプリからコピー先のフィールドへ値を写す。
  キーのフィールドを LinkField (か TextField) にし、コピー先のフィールドは読み取り専用 (上の「読み取り専用の列」) にする。相手に無い値を保存するとエラーになる
- 結べるのは同じ kintone のデータソースのモジュール同士だけ (相手のアプリも同じデータソースの `Apps` に書いてもらう)。kintone のモジュールと DB のモジュールを LinkField の結合で結ばない
- 関連レコード一覧に当たる画面: 相手のモジュールの一覧 (ListField) を置き、`SearchCondition.Condition` に `FieldVariableMatchCondition` (`SearchTargetVariable` = 相手の側のフィールドの `Value`、`Variable` = こちらのフィールドの `Value`) を書く

### テーブル

kintone のテーブルは、テーブルの定義に親のアプリの文字列の列 (テーブルのフィールドコード) として出てくる。行は親のモジュールの一覧 (ListField) にする。
作りは「行データを親の列に JSON 配列で保存する一覧 (ListField の `DbColumn`)」と同じ。

| 設定 | 書く値 |
|---|---|
| 親の ListField の `DbColumn` | テーブルのフィールドコード |
| ListField の `SearchCondition` | `ModuleName` = 行のモジュール、`LimitCount: null` |
| 行のモジュール | `DataSourceName`・`DbTable`・Id フィールドなし。ルートの JsonField 1 つに、行の項目をノードとして並べる |
| ノードの `Key`・行のフィールドの `DbColumn` | テーブルの中のフィールドコードそのまま (メタ情報のファイルの、テーブルの列の `Fields`) |

- 行の ID (`$id`) はノードにもフィールドにもしなくてよい (結び付けていないキーとして行に残り、保存のときに使われる)
- ノードの型: 数値は Number のノード + NumberField、日付は Date のノード + DateField、時刻は Time のノード + TimeField、日時は DateTime のノード + DateTimeField (`SaveAsUtc: true`)、
  ラジオボタン・ドロップダウンは Text のノード + SelectField、文字列は Text のノード + TextField
- 行の中の計算・ルックアップでコピーされるフィールドは読み取り専用 (ノードにしてよいが、行のレイアウトで `IsViewOnly: true`。保存では送られない)
- ノードにする項目は、行の項目のうち画面で使うものだけ。ノードにしていない項目は、今ある行では変わらず、新しい行では空 (kintone の初期値) になる
- テーブルは詳細のレイアウトに置く。親のテーブルの列を検索条件・並び・集計に使わない (エラーになる)
- テーブルは親のレコードと一緒に 1 回で保存される (行ごとに分かれない)。親の一覧の画面で行を足す・直す・消すなら ListField の `CanCreate` / `CanUpdate` / `CanDelete` を true

### 論理削除・楽観ロック

- 楽観ロック: `Name: "OptimisticLocking"` の OptimisticLockingField (`IncrementVersion: true`) を `DbColumn: "$revision"` に結ぶ。
  読んだときの版と違えば (ほかの人が kintone か別の画面で先に更新していれば) 保存がエラーになる。版は kintone が進める。kintone のモジュールにはこれを付ける
- 論理削除: 削除済みを 1 で持つ数値のフィールドを kintone のアプリに作ってもらい、`Name: "LogicalDelete"` の BooleanField を結ぶ (kintone の画面には削除済みのレコードも出る)
- どちらもレイアウトには置かない (DB のモジュールと同じ)

## 検索・並び

使えるもの: 比較 (等しい・等しくない・大小)・部分一致・空欄・候補の中のどれか (In)・and / or / not・日付や数値の範囲・並び・ページング・件数。
kintone のフィールドの種類ごとに、使える条件が決まっている (使えない組み合わせはエラーになる)。

| フィールド | 使える条件 |
|---|---|
| 文字列 (1 行)・リンク | 等しい・等しくない・部分一致・In・空欄 |
| 数値・計算・レコード ID (`$id`) | 等しい・等しくない・大小・In・空欄 |
| 日付・時刻・日時・作成日時・更新日時 | 等しい・等しくない・大小・空欄 |
| 文字列 (複数行) | 部分一致・空欄 (等しい・In は使えない) |
| リッチエディター | 部分一致 (「含まない」・空欄は使えない) |
| ラジオボタン・ドロップダウン・ステータス・作成者・更新者 | 等しい・等しくない・In・空欄 (部分一致・大小は使えない) |
| チェックボックス・複数選択・ユーザー選択など | 等しい (= 含む)・In・空欄 |
| レコード番号 | 等しい・等しくない・大小・In (値は番号の数字) |
| テーブル・添付ファイル・`$revision` | 使えない |

- 部分一致は kintone の検索の動きに従う (語の区切り方によって、文字の途中からの一致が見つからないことがある)
- 並びに使えるのは、文字列 (1 行)・数値・計算・日付・時刻・日時・ラジオボタン・ドロップダウン・レコード番号・レコード ID など、kintone が並べられるフィールド。複数行の文字列・値が複数のフィールド・テーブルでは並べられない
- ページングで読めるのは、条件に合うレコードの先頭から 10000 件まで (kintone の制限)。それより後ろのページはエラーになる。件数の多いアプリの一覧は、検索条件で絞れるようにする

DB のモジュールと同じ書き方で使えるもの (コネクターが相手のアプリを先に読んで値を集める):

- LinkField 越しの項目 (相手のアプリのフィールド。リンク先のリンクも) での検索・並び・表示
- 相手のモジュールの一覧 (親子の一覧) の項目での検索 (すべて含む・存在する/しない・否定も)
- 集計 (件数・重複なしの件数・合計・平均・最小・最大。軸・条件・集計後の絞り込み・並び・上位の件数・クロス集計)
- 日付・日時の項目を期間 (年・四半期・月・週・日・時) でまとめる集計の軸 (`DateGroup`。年度の開始月・UTC で保存した日時の時差も DB と同じ意味)

件数の上限 (データソースの `MaxRows`、既定 10000) を超えるとエラーになるもの:

- 集計 (kintone に集計の機能は無いので、条件に合うレコードを全部読んで集計する)。件数の多いアプリの集計は、期間などの条件を必ず付ける
- LinkField 越しの項目・一覧の項目での検索で、相手のアプリに当たるレコード
- LinkField 越しの項目での並び (条件に合うレコードを全部読んで並べる)

使えないもの (エラーになる):

- 列どうしの比較・JSON の列のノード・意味検索のようなフィールド独自の検索条件

文字の比較と並びは kintone に従う。DB と同じ結果になるとは限らない。
LinkField 越しの項目で並べるときはコネクターが並べる (空欄は昇順で先・文字は文字コードの順)。集計の結果もコネクターが並べる (空欄は昇順で後・文字は文字コードの順)。

## 保存

- **kintone への保存はレコード 1 件ごとに確定する。** 同じ保存の中のほかの処理が失敗しても戻らない (ロールバックしない)。
  1 回の保存で kintone のレコードを複数書く画面 (親と、別のアプリの子の一覧) や、kintone と DB を一緒に書く画面は、途中まで保存された状態が起こりうる。
  そろっていないと困る組み合わせは、kintone のテーブルにする (親と一緒に 1 回で保存される) か、画面 (保存の単位) を分ける
- 更新は変えたフィールドだけを送る。新規で空のフィールドは送らない (kintone の初期値が効く)
- kintone の必須・重複禁止・値の範囲・選択肢に無い値は kintone 側で確かめられる。そこで止まれば保存がエラーになる
- 保存は接続の API トークン (か連携用のアカウント) の権限で行われる。kintone の更新者は、API トークンなら Administrator、アカウントならそのアカウントになる。画面のユーザーごとの kintone の権限にはならない

## やってはいけないこと

- **kintone のデータソースで SQL を書かない** (QueryField のモジュール、ExecuteSqlField)。kintone のデータソースでは SQL もストアドプロシージャも実行できない
- **DateTimeField を `SaveAsUtc: false` にしない**。kintone の日時は UTC なので、false にすると 9 時間ずれる
- **読み取り専用の列を入力できるレイアウトに置かない** (保存がエラーになる)
- **1 回の保存で kintone のレコードと DB のテーブルの両方がそろって保存される前提にしない** (上の「保存」)
- **kintone のモジュールと DB のモジュールを LinkField の結合で結ばない**
- **Id フィールドを `$id` と重複禁止のフィールド以外に結ばない** (更新・削除がエラーになる)

## 扱えないもの

- テーブルの中の添付ファイルの読み書き (テーブルの中のものは読み取り専用)
- プロセス管理の操作 (ステータスを進める・作業者を変える)。ステータスと作業者は読むだけ
- レコードのコメント、アプリやフォームの設定の変更
- テーブルの行を、親をまたいで一覧・検索・集計すること
- 作成者・更新者・ユーザー選択の表示名での検索 (ログイン名で探す)
- 選択肢を kintone から画面のたびに読むこと (Enum の定義に写して使う)
- 上の「使えないもの」の集計・検索
